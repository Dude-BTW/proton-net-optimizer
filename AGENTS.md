# AGENTS.md

## Role
You own this repository. Maintain and evolve the tooling that (1) recommends
the least-loaded Proton VPN server by runtime measurements and (2) keeps the
Arch Linux mirror list matched to the current VPN exit country.

The user makes the connection decision. The tool measures, ranks and presents;
it must never switch servers on its own.

## Environment
- Arch Linux, KDE Plasma 6, Wayland.
- Agent/inference: OpenCode.
- VPN: Proton VPN daemon, `protonvpn` CLI and `proton-vpn-gtk-app`.
- Packages: pacman and `/etc/pacman.d/mirrorlist`.
- Language: Python (the whole project, including helpers). Shell only through
  `subprocess`, never for logic.
- The project runs in `.venv/` (git-ignored). Recreate it with:

  ```bash
  python3 -m venv .venv
  .venv/bin/pip install -e ".[dev,tui]"
  ```

  Call `.venv/bin/python` directly; do not rely on activation between agent
  shell calls.

## Server inventory
`pno/data/inventory.toml` holds the entries the setup knows about:

`IS-US#1, IS, CH-JP#2, CH-US#3, CH-DE#2, CH-PL#2, CH-UA#2, CH, SE-PL#1, SE-UA#1, SE`

- `ENTRY-EXIT#N` entries are Secure Core logical servers; `CH-US#3` means entry
  Switzerland, exit United States.
- Bare two-letter entries are regular countries the user tracks.
- The inventory is **data only**: never encode a preference or order between
  entries, countries or mirrors. Every order is computed from live data.
- The “all countries” server view is not limited to the inventory; the
  inventory defines Secure Core aggregates and favourites.

## Data sources
- Server loads: `pno/proton/fetch_helper.py`, executed with `/usr/bin/python3`
  so it can use the Proton libraries already installed system-wide. It reuses
  the GUI session/cache; this project stores no credentials.
- Fallbacks: `~/.cache/Proton/VPN/serverlist.json`, then the compact cache in
  the state directory. Stale data must be flagged, never presented as fresh.
- Connection state: NetworkManager (`nmcli`), fallback `protonvpn status`.
  The exit country from the logical server drives the mirror target.
- Mirrors: `https://archlinux.org/mirrors/status/json/` plus a runtime latency
  probe of `core.db`. Never write `rsync://` entries; pacman cannot use them.
- Country code mapping (`UK`→`GB`) and EN/UK names live in
  `pno/data/countries.toml` and are regenerated by `tools/gen_countries.py`.

## Constraints
- Secure Core servers are outside automatic selection; they are shown as
  aggregates per exit country.
- No hardcoded priority between servers, countries or mirrors.
- Credentials never enter the repo; read them from Proton's own storage or
  environment, never log them.
- Do not alter VPN client or pacman configuration beyond what a task needs.
  Taking ownership of `mirrorlist` requires disabling `reflector.timer`, with
  the user's confirmation (`pno install` asks; `--keep-reflector` opts out).
- The privileged mirror helper must stay self-contained, standard-library
  only, root-owned, and validated line by line. Never let it import
  user-writable code.
- Auto-switch, auto-connect and auto-disconnect are out of scope. Only the
  user's explicit Connect action (CLI/TUI/tray) may call `protonvpn connect`.

## CLI / TUI / tray parity
- `pno/cli.py` is the single source of truth for commands and flags.
- The TUI and tray must not invent behaviour the CLI cannot express. When a
  user-facing action is added, update all three entry points and `README.md`.
- Machine contracts stay English: CLI flags, JSON keys, event names, log
  fields. The TUI is bilingual (EN default, UK selectable); every new visible
  string goes to both `pno/tui/i18n/en.py` and `pno/tui/i18n/uk.py` in the same
  change, and `tests/test_i18n.py` must pass.
- Every command returning structured data accepts `--json` and must keep
  stdout pure JSON in that mode.

## Reliability
- Atomic writes everywhere (temporary file + `fsync` + `os.replace`); shared
  caches and mirror apply serialised with `flock`.
- Every subprocess and HTTP call has a timeout and raises a typed `PnoError`.
  Errors surface; they are never swallowed.
- Re-running a command with nothing to change must change nothing (mirror
  apply compares `Server =` lines and skips the write).
- The daemon must survive network loss, crashes and reboot. Pause state,
  schedule and last errors are persisted in `state.json`.
- Machine logs are JSONL in `$XDG_STATE_HOME/proton-net-optimizer/logs/`.
  Redact secrets, rotate by size, tolerate a torn last line.

## Layout
- `pno/cli.py` — argparse entry point; `pno/daemon.py` — scheduler and IPC.
- `pno/proton/` — helper, cache, status and selection.
- `pno/mirrors/` — status, probe, planner, apply, root helper.
- `pno/tui/` — Textual UI and i18n; `pno/tray/` — PySide6 tray.
- `pno/install.py` — user unit, autostart, sudoers helper.
- `pno/data/` — inventory, generated country names, unit templates.
- `tests/` — offline suite only.

## Working rules
- Answer the user in Ukrainian.
- Write code, comments, docs, filenames and commit messages in English.
- Small verifiable steps; measure before and after claiming a change.
- Report what was measured, what changed, what failed. No speculation.
- Run the full check set before considering a change done:

  ```bash
  .venv/bin/python -m pytest
  .venv/bin/ruff check .
  .venv/bin/black --check .
  .venv/bin/isort --check-only .
  .venv/bin/mypy pno
  ```

## Definition of done
- Each objective (server suggestions, mirror refresh, automation) is invocable
  independently and idempotent.
- Nothing blocks on interactive input outside explicit install/uninstall
  prompts; errors surface with a typed code and a hint.
- Pause/resume works with and without the daemon.
- Re-running the tools changes nothing when nothing needs to change.
